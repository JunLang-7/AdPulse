# AdPulse

> 主动发现市场信号，辅助下一步投放决策。

AdPulse 是一个处于产品探索阶段的**主动式营销投放决策助手**。

它围绕企业的推广目标与当前方案，结合外部市场信息和自身投放表现，主动发现值得关注的变化，帮助市场与营销人员判断下一步应该延续什么、调整什么、尝试什么，以及什么时候应该暂停。

**当前仓库仅记录初步产品定位，尚无可运行的软件。** 产品范围、用户细分、交互形态与商业模式仍需调研验证；不预设架构或技术选型。

## 为谁解决什么问题

目标用户是需要对推广投入作出判断的市场与营销人员，初步研究范围为山东企业，暂不按行业确定首发客群。

待验证的问题是：市场信息与自身投放结果分散，用户难以及时发现重要变化，也难以将这些变化转化为有依据的下一步投入决策。

AdPulse 希望帮助用户回答：

- 最近发生了哪些与当前推广有关的重要变化？
- 这些变化是否值得影响当前方案？依据是什么？
- 下一步应该调整卖点、内容、人群、渠道、合作对象，还是预算？
- 应该先做什么小规模验证，观察哪些结果，再决定是否继续？

市场动态是输入，**有依据、可控制、可验证的投放决策**才是目标。

## 核心：主动发现，而不是等待提问

用户不必每天先问「今天有什么值得关注」。产品应持续围绕用户的目标与关注范围，主动识别信号，并说明它与当前投放的关系。

重点探索三类信号：

1. **市场变化**：用户需求、竞品动作、内容方向及平台环境中与当前推广有关的变化。
2. **效果变化**：自身投放成本、有效咨询、成交等表现的变化。
3. **假设偏差**：当前方案依赖的判断开始得到支持，或受到新证据挑战。

新信息不一定代表变化，变化也不一定需要行动。没有历史对照时，不应把新发现包装成趋势；证据不足时，应明确说明并建议继续观察或补充核实。

## 方案是判断基线，不是使用门槛

- **已有方案**：理解用户的目标、受众、渠道、预算和正在执行的安排，作为持续观察与提出建议的基线。
- **没有方案**：AI 根据真实业务情况与可用材料生成起步草案，由用户确认；缺失信息应标为未知或待确认，不编造预算、历史效果或经营目标。

方案不是一次生成后就结束的文档，而是持续回答「现在为什么这样投」的依据。

## 用户可控

用户应能够调整关注范围、提醒条件与行动边界。控制台或其他配置入口是待探索的交互方式，不是已经确定的产品形态。

- **关注范围**：关注哪些对象、问题、来源与渠道，排除什么。
- **提醒条件**：哪些事件立即提醒，哪些进入定期汇总；可量化的变化可设置明确阈值。
- **行动边界**：可用预算、可接受的试验范围，以及必须人工确认的事项。

默认方式应能帮助用户开始使用，自定义用于逐步纠偏，而不是要求用户先完成复杂配置。重要性判断不应只依赖一个不可解释的综合分数。

## 初步工作闭环

**建立推广基线 → 持续发现信号 → 人工核实关键依据 → 判断对当前方案的影响 → 形成调整草案与预算安排 → 用户确认行动 → 录入或接收实际结果 → 更新下一轮关注与判断。**

这是业务逻辑，不是页面菜单，也不是必须逐步完成的向导。产品可以先提醒、再补证，用户也可以选择忽略、继续跟踪或暂不调整。

调整建议应交代：

- 发生了什么，以及原始依据在哪里；
- 为什么可能影响当前方案；
- 哪些是事实、哪些是推断，还有哪些不知道；
- 建议改变什么、需要多少投入，以及其他可选方向；
- 如何验证，什么情况下继续、调整或停止。

## 投放范围与效果边界

初步同时考虑：

- 平台付费广告；
- 达人合作与内容种草。

两者可以围绕同一推广目标作出投入选择，但不能强行使用同一种效果衡量方式。能计算的计算，能比较的比较，无法归因或数据不完整的部分应明确保留。

外部市场信息主要帮助发现值得验证的方向；自身真实投放数据主要帮助判断是否继续投入。公开内容不等于竞品真实花费和收益，讨论热度、曝光和点击也不等于利润。

主动发现不等于自动执行。当前定位以建议、草案与人工确认为中心，不默认自动改预算、下单投放或中止合作，不承诺保证收益或找到最优预算。

## 待验证的问题

- 哪一类企业和哪一种投放场景最值得优先服务？实际使用者、受益者与付费者分别是谁？
- 哪些遗漏事件会影响真实决策，用户目前通过什么办法处理？
- 相比舆情监测、投放平台、AI研究工具和人工信息渠道，AdPulse 提供什么额外价值？
- 用户能够提供哪些成本、成交与收益数据？数据缺口如何影响建议？
- 怎样平衡主动提醒与噪音，怎样衡量漏报、误报和建议的实际价值？
- 用户愿意在哪里接收、阅读与处理信息：App、Web、IM、小程序，还是其他方式？
- 用户是否愿意持续使用并付费，服务成本是否可持续？

产品形态应根据真实使用场景决定，不因已有原型或某项采集能力提前锁定。

## 候选能力：Agent-Reach

[Agent-Reach](https://github.com/Panniantong/Agent-Reach) 是待评估的外部信息搜索与读取能力来源，**尚未集成**。

是否采用，应由目标用户需要的信息、渠道可用性、授权与合规要求、隐私边界和服务成本共同决定，不由工具支持的平台数量反推产品范围。
