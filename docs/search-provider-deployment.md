# 企业官网发现（搜索源）部署指南

> 面向管理员：如何配置百度千帆 / Tavily 等搜索源密钥，让「只填企业名 → 自动发现官网 → 采集新闻」链路可用。
> 本文随代码维护，配置模板见 [.env.example](../.env.example)。

## 1. 这套机制是什么、依赖什么

用户在控制台登记一家企业（只填企业名，如「美的」）后，系统会：

1. **搜索**候选站点（调用搜索 API，不抓任何搜索结果页）；
2. **验证**首页归属（标题含品牌 + 官网类词）；
3. **解析**出真正的新闻列表页；
4. **采集**标题与链接（robots 遵从、不抓正文）；
5. 失败时**换站重试**（有失败退避，不无限烧额度）。

链路质量取决于**搜索源的召回质量**。国内企业的官网在国内索引里排名明显更好。

## 2. 源与费用（含免费额度）

| 源 | 环境变量 | 免费额度 | 说明 |
| --- | --- | --- | --- |
| **百度千帆 AI 搜索**（推荐首选） | `BAIDU_QIANFAN_API_KEY` | **1500 次/月**（按天发放约 50 次） | 中文召回最好；接口 `POST https://qianfan.baidubce.com/v2/ai_search/web_search` |
| **Tavily**（推荐次选） | `TAVILY_API_KEY` | 1000 次/月 | 申请最简单（Google 账号登录）；`POST https://api.tavily.com/search` |
| Exa 官方 API | `EXA_API_KEY` | 有免费额度 | 语义检索，英文强 |
| Tavily 之外的 Google 结果 | `SERPER_API_KEY` | 2500 次试用 | `https://serper.dev` |
| Brave | `BRAVE_API_KEY` | 2000 次/月 | `https://brave.com/search/api/` |
| agent-reach CLI（Exa） | `AGENT_REACH_BIN` | 免费但限流（50/天） | 需独立 Python 环境，见开发指南 §Agent-Reach |
| **Bing RSS** | 无需 Key | 200 次/天 | **默认启用**；中文召回一般（实测海尔选错站） |
| 博查 | `BOCHA_API_KEY` | 按次付费 | **本项目已决定不启用**，不配即可 |

**不配任何 Key 也能跑**（只用 Bing），但中文企业召回质量差。**最少配百度千帆一个**即可显著改善；百度 + Tavily 双源实测 6 家企业全部正确（见下）。

## 3. 申请步骤（管理员操作，各约 5 分钟）

### 3.1 百度千帆（推荐先配）

1. 打开 [千帆控制台](https://console.bce.baidu.com/qianfan/)，用百度账号登录（需实名认证）。
2. 进入「千帆大模型平台」。
3. 左侧菜单「应用接入」或「API Key 管理」→ **创建 API Key**。
4. 复制形如 `bce-v3/ALTAK-xxxx/yyyy` 的完整字符串。
5. **额度确认**：搜索 API 每月 1500 次免费（按天发放约 50 次），超出才按量计费；默认限流 1 QPS。

### 3.2 Tavily

1. 打开 [app.tavily.com](https://app.tavily.com)，用 Google/GitHub 账号登录（无需绑卡）。
2. 首页直接显示 `tvly-` 开头的 Key，复制。

### 3.3 填入配置

在部署环境的 `.env`（本地）或环境变量（生产）中：

```bash
BAIDU_QIANFAN_API_KEY=bce-v3/ALTAK-xxxx/yyyy
TAVILY_API_KEY=tvly-xxxxxxxx
```

**安全要求**：
- `.env` 已被 `.gitignore` 排除，**不得提交到仓库**；
- 不要把 Key 写进聊天记录、截图或共享文档；
- 若 Key 曾外泄（如贴在群里），立即到对应平台**重置**；
- 生产环境建议用部署平台的 secret 管理注入，不落盘明文。

## 4. 额度保护（系统内建，无需额外设置）

系统对每个源有**独立的每日限额**，防止单源被刷爆：

```
默认（不配置 SEARCH_DAILY_LIMITS 时）：
  baidu: 100/天    ← 千帆 50 次/天的平台免费额度是瓶颈，系统闸门更宽
  bocha: 100/天
  bing:  200/天
  exa:   50/天
  serper / brave / exa-api / tavily: 100/天
```

需要调整时（示例）：

```bash
# 千帆平台免费只有约 50 次/天，系统里调到 50 更符合实际
SEARCH_DAILY_LIMITS=baidu:50,tavily:100,bing:200
```

**实际消耗参考**（实测）：登记 1 家企业（含发现 + 验证 + 首次采集）约消耗 **3–5 次搜索**；换站再消耗 2–4 次。按千帆 50 次/天计，一天可支持 10+ 家企业的自动发现，日常手动刷新更省。

## 5. 部署后验收（15 分钟）

配置完成后按顺序验证：

1. **重启服务**，确认启动日志无「未配置 XX_API_KEY」类报错。
2. **登记「美的」**（只填企业名）→ 等待发现完成。
   期望：`host = www.midea.com.cn`、`listUrl = /zh/about-midea/news`、`lastOutcome = ok`、线索 ≥ 10 条。
3. **登记「海尔」**→ 期望 `host = www.haier.com`、线索 ≥ 5 条。
4. 任意一家 `failed` 时，查看失败原因是否如实（robots / JS 渲染 / 无列表页），**不要出现选错公司**的情况。

## 6. 已知限制与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 某企业选错站 | 搜索召回不理想 | 先确认双源已配；仍错则手动填该企业真实新闻列表页地址 |
| `robots 检查失败，保守跳过` | 目标站 WAF/网络不可达 | 合规红线，不绕过；换其他入口站或手动填地址 |
| `列表页…没有找到可用条目` | 目标站 JS 渲染 | 手动填可解析的列表页地址 |
| `refresh_too_soon` (429) | 5 分钟冷却 | 稍后再试 |
| 源报 `quota_exhausted` | 当日额度用完 | 次日恢复；或调 `SEARCH_DAILY_LIMITS` |

## 7. 故障回退

- **任一源失败不影响其他源**：多源按顺序聚合，单个源额度用完/限流只影响自己。
- **全部源失败**：发现与采集如实报错，不会乱选站点；已有条目不受影响。
- **回退到无 Key 状态**：删除环境变量重启即可，退回 Bing 单源（质量下降但可用）。
