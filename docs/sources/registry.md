# 来源准入登记表（#39 / #41）

本表是**登记**，不是合规结论。它记录「目前允许碰哪些站点、碰哪一部分、谁负责、出事怎么办」，
以及「哪些还没拿到依据」。任何对外材料都不得把本表说成「已获授权」「官方合作」或「已通过来源准入」。

- 代码唯一真源：`packages/core/src/sources.ts` 的 `SOURCE_DEFINITIONS`（allowlist）。本表与之对齐，
  `tests/source-registry.test.ts` 会在两边不一致时失败。
- 采集能力：`SourceService`（robots、每日请求上限、大小/超时、重定向与 SSRF 拒绝、`stopped`、`purge`、快照保留）。
- 线索展示（#39 方案 A）：`SourceLeadService` + `GET /api/me/source-leads`，本人逐来源开启，
  **不自动建事件、不自动推送**。

## 3. 内容与保留规则

| 项 | 规则 |
| --- | --- |
| 取得内容 | 仅列表标题、原文链接、列表展示日期；**不读正文、不存页面文本** |
| 发布时间 | 只取列表展示日期；缺失、相对时间、未来日期、解析失败一律 `null`，不由 URL 推导 |
| 快照 | 只存 `item_key` 与标题哈希，保留 30 天后由调度器清理 |
| 标题订正 | 记 `title_updated_at`，不计展示配额 |
| `purged` | 投诉/下架/撤销后删除标题并置 `purged`，后续命中跳过、不得重新入库 |

## 4. 失败、停用与投诉

- 403 / 429 / 验证码 / 条款变更 → 立即 `stopped`，不自动重试；`stopped` 只能人工 `resume`。
- 5xx / 超时 / 解析失败 → 退避重试；**任何失败都不改动既有条目状态**。
- robots：2xx 按 `Disallow`/`Allow`/`Crawl-delay` 执行（Allow 优先于更短路径的 Disallow）；4xx 视为无限制；
  5xx/不可达/非 robots 内容保守视为全禁。
- 投诉、下架要求、条款变更、`stopped` 超过 7 天 → 24 小时内停用来源并执行 `purge(source_key)`，
  留痕（谁、何时、范围、原因）；恢复须人工复核并重走 Gate 0。
- 运维命令与排障顺序见开发指南 §7。

## 6. 扩容门禁

新增站点、新增主机、扩大内容范围（如读正文）或新增主体映射，均须**重走 #41 Gate 0**：
条款原文快照 + 功能事实描述 + 风险承接签核，缺一不可。禁止在运行期通过配置新增来源。
