### 投递闸门（`local-real`）

用构造的 `initiatedBy=system` 会话验证：

- 未授权：投递 `suppressed` + `consent_missing`，**渠道未被调用**；
- 授权后：正常 `sent`；
- 用户自己的会话：不受授权闸门限制；
- 地址失效后：`suppressed` + `destination_invalidated`。

会话由测试夹具构造，不是平台真实推送，因此标注 `local-real`，不勾选真机项。

### 地址失效判定

- 平台返回 `230002` / `230013` / `99992351` → 投递 `failed` 且不重试，地址一次即置 `invalidated`；
- 发往**他人**地址的失败不会牵连本人地址（收件人匹配校验）；
- 身份绑定撤销只抑制投递，不改地址状态。

两条都有带变异验证的测试（去掉收件人匹配、去掉抑制终态，对应测试会失败）。

## 设计边界（写进代码与文档）

- `destination` 与 `consent` 分开建模：撤销不等于注销，地址仍在。
- 闸门只约束 `initiatedBy=system` 的投递；用户自己的会话不受影响。
- `initiatedBy` 不接受 API 入参，只由服务内部设置——调用方不能自己声明「我是系统」。
- `expectedVersion` 必填：旧请求重放无法覆盖后来的撤销。
