# Proposal：观策AI——面向当前投放任务的市场信号提醒

## 1. 动机与用户故事

### 1.1 动机

品牌团队需要结合消费者讨论、竞品动态和自身投放效果作决策。这些信息分散在搜索结果、投放报表和人工记录中，团队要反复整理背景、核对来源，才能判断变化是否影响当前任务，容易错过素材上线或策略调整的窗口。

观策AI希望围绕当前推广任务主动筛选值得关注的变化，让用户看清依据、影响与可采取的行动。本提案聚焦提醒的判断规则与交互，尚待访谈和原型验证。

### 1.2 用户故事

- **外部变化提醒**：作为品牌方市场人员，我希望及时发现影响当前推广任务的消费者讨论变化或竞品事件，了解依据与处理时限，以便决定是否调整素材或投放节奏。
- **自身效果排查**：作为投放优化人员，我希望自身效果指标超过项目警戒线时收到排查提示，并看清已知事实与待验证原因，以便安排核查和小规模测试。

## 2. 目标用户与产品定位

目标用户为品牌方市场与广告投放团队，具体企业类型与首发场景仍需验证。

观策AI是一款主动式营销投放决策助手：结合推广目标、当前方案与可用数据，提示值得处理的变化，并给出有依据、可控、可验证的调整建议。初步覆盖付费广告、达人合作与内容种草，调整对象包括受众、内容卖点、广告创意、渠道预算与投放节奏，由用户确认行动并录入实际结果。

## 3. 现有做法及不足

拟通过访谈验证的现有做法包括人工搜索、表格整理、查看投放报表和向通用AI提问。核心缺口是用户仍要自行建立“新信息—当前任务—调整决策”的联系。本提案要验证主动提醒是否能减少这部分判断工作，以及误报和提醒频率是否可接受。

## 4. 本期范围

本期确定信号识别、提醒分级、证据展示、比较规则与反馈机制，并将有效提醒关联到策略调整草案。

原型使用用户导入或已获授权的信息，以及用户录入或导入的投放数据；接入、模型连接与自动同步能力另行验证。引用聚光文档用于说明指标差异，不代表已接入聚光。

本期不包含自动调价或执行广告投放、未经授权的平台采集、全网实时监控及收益保证。

## 5. 关键判断规则

### 5.1 什么变化值得提醒

提醒须说明发生了什么、影响哪项推广判断、依据是什么，以及用户能在何时采取什么行动。热度或涨幅不能单独决定提醒级别。

| 信号类型 | 成立依据 | 支持的处理 |
| --- | --- | --- |
| 消费者讨论趋势 | 前后样本统计规则一致，变化达到项目设定条件，并关联当前任务 | 提出卖点或创意测试假设；结论限于所收集样本 |
| 竞品明确事件 | 可靠一手公告，且事件内容和适用条件影响当前任务 | 核查素材、价格表达或上线节奏；不要求先有历史趋势 |
| 自身效果异常 | 同一报表指标与统计范围，数据完整，并超过项目警戒线 | 触发排查；外部讨论只能作为待核查线索 |

社区讨论本身不足以支持扩大预算；预算建议还需本品牌效果数据。调整后的效果变化用于复盘，不能仅凭前后变化认定由某条提醒或某次调整造成。

提醒等级按处理窗口区分：**及时提醒**用于等待汇总会错过的事项；**定时汇总**用于下一轮评审可处理的事项；其余证据不足、关联较弱或重复的信息**保留供查**。同一事件合并展示，新增证据显著改变判断或行动窗口时再提醒。

### 5.2 “数据口径”说明了什么

数据口径就是一个数字“统计谁、统计哪些行为、覆盖多长时间、如何去重和计算”。同名数字也可能有不同含义。

本提案引用的小红书聚光帮助中心解释了广告报表的相关统计规则。例如，笔记前台点赞数统计该笔记本身的点赞；聚光报表的点赞量还可能计入用户经广告进入作者主页后，对该作者其他笔记的点赞。因此，两者的差额不能直接解释成数据错误或投放带来的新增点赞。[1]

对应到本产品：

| 数据 | 使用前需保留的说明 |
| --- | --- |
| 公开内容样本 | 来源、搜索词与筛选规则、发布时间范围、排序与样本上限、获取时间、去重及主题判定规则 |
| 投放效果报表 | 原始报表与指标名、账户或计划范围、统计日期、计算公式、去重规则、归因窗口及数据回传状态 |

归因窗口指某次点击或曝光之后，多长时间内发生的行为会计入该广告。效果指标沿用所导入报表的定义，不将前台互动、广告归因数据、咨询次数和有效线索数混算。

### 5.3 什么叫“暂不能比较”

“暂不能比较”是指两期数字的统计对象或规则不同，无法判断差额来自真实变化，还是来自搜索、筛选或计数方式的改变。两期都收集了120条内容，也不代表它们可比。

讨论趋势需核对相同来源、搜索范围、筛选与排序方式、样本上限、去重及主题判定规则，并使用等长且完整的时间段。这里判断的是**所收集样本中的主题占比变化**，不外推为整个平台消费者的需求变化。

效果指标则需核对同一指标定义、统计对象、时间与归因规则，并确认两期数据均已回传完整。规则不一致时说明具体差异；尚未完整时标为“数据待补齐”。两者都暂停生成相应涨跌结论。

### 5.4 搜索词变化后怎么办

搜索词影响哪些内容会进入样本。若将“通勤背包”改为“防雨背包”，新样本本来就更容易包含防雨讨论，不能把前后差额写成消费者关注上升。系统应执行以下处理：

1. **记录变更并中断直接对比**：保留原数据、变更时间和前后搜索范围，在详情中显示“搜索范围已变，本次不显示涨幅”，不拼接新旧序列。
2. **能回补时统一重算**：若数据源能完整恢复两期内容，按同一套规则重建两期样本，核对覆盖范围与完整性后再比较，并注明回补时间。只换成同一个搜索词重新搜索，不能自动证明可比。
3. **不能回补时建立新基线**：保留旧序列供查，新规则下首个完整周期作为基线；到下一完整、等长且规则一致的周期，再判断变化。期间显示“新搜索范围观察中”。

暂停的是受影响的趋势比较。新搜索结果仍可作为创意线索；可靠的竞品公告等明确事件仍按5.1处理。

## 6. 基本概念与信息结构

| 对象 | 保留的信息 |
| --- | --- |
| 推广任务 | 产品、受众、目标、预算、当前策略与执行时间；缺失项标为待确认 |
| 证据记录 | 原始链接或报表、来源类型、发布时间与获取时间、内容片段，以及5.2所列统计说明 |
| 提醒记录 | 关联任务、变化或事件、引用证据、比较状态及原因、判断局限、等级、建议动作与处理时限 |
| 反馈记录 | 采纳、忽略、误报原因或补充证据，关联调整与结果；修正时保留原判断和修改记录 |

以下为待验证的页面职责，不表示已有可运行功能。单条提醒的证据与判断集中在详情页，其余页面引用摘要。

| 候选入口 | 页面职责 |
| --- | --- |

| 投广方案 | 引用提醒摘要，编辑受众、卖点、创意、预算与节奏，记录用户确认的调整草案 |
| 数据看板 | 汇总处理情况、误报和实际结果，单条依据与反馈跳转详情查看 |

## 8. 验收标准

以下数字均为演示数据，不代表真实投放结果。变化阈值、样本量要求、警戒线与提醒频率需在项目中明确设置。

| 验证情形 | 输入与预期结果 |
| --- | --- |
| 消费者讨论变化 | 相邻两期各7天，按同一规则取得并去重的有效样本各120条，防雨相关内容由12条增至36条。满足项目条件时，显示样本占比由10%升至30%（增加20个百分点），进入汇总并建议创意测试；不据此扩大预算 |
| 竞品限时促销 | 官方公告确认明日降价，且适用条件影响我方待上线的价格素材。及时提醒并展示原文、条件与处理期限 |
| 自身成本异常 | 某导入报表将咨询成本定义为广告消耗÷咨询次数；两期均为完整7天、同一计划与统计规则。消耗均为5000元，咨询由100次降至50次，成本由50元升至100元，超过项目警戒线70元。提示排查，不认定外部讨论为原因 |
| 搜索范围改变且不能回补 | 搜索词由“通勤背包”改为“防雨背包”。不显示跨规则涨幅，展示变更原因并建立新基线；新规则下第二个完整、等长且规则一致的周期结束后再比较 |
| 搜索范围改变且可以回补 | 数据源可完整恢复两期内容。按统一规则重建两期并核对覆盖与完整性，保留原记录及回补说明，再生成比较结果 |
| 数据尚未完整 | 一期效果数据尚未完成回传。展示“数据待补齐”，暂停该指标的涨跌与异常结论，补齐后重新判断 |
| 去重与纠错 | 转载或已处理事件不重复提醒；用户可补充链接、说明误报原因。修正保留原判断与修改记录，显著影响处理的新增证据可再次提醒 |
