# Proposal：从效果证据到人工决策的最小闭环（修订稿）

状态：待评审的增量规格。关联 [总提案 #6](https://github.com/JunLang-7/AdPulse/issues/6) 与 #7–#12。
逐条正文见[Issue修订文本](effect-evidence-issues.md)。
本次只修订规格、依赖和验收，未实现下述新接口、数据模型或交互；不据本 PR 标记 Proposal-Accepted，也不关闭业务子任务。
历史设计 #2 及其原文评论保持不变。后续实现分别提交小 PR。

## 1. 基线与本期交付

核对基线为 [140a0a6](https://github.com/JunLang-7/AdPulse/commit/140a0a67334261ca23496334ecb8fd8c0356b245)。
现有代码提供会话、冻结候选、inbox/job/delivery、策略快照和会话列表/详情页；默认 reviewPolicy 不调整策略。
Signal 目前只有展示摘要，没有完整的效果证据、比较结果或提醒实体。

已知接口约束：Session 创建要求已注册 recipient 账户；非演示运行时也要求渠道账户。
因此“纯 Web 不受飞书阻塞”尚不是现有实现能力，必须在 #10 中提供真正不发送 IM 的控制台会话路径。
现有 demo 模拟回执不能作为该路径的生产实现或飞书验收证据。

本期交付一条 Web 路径：
保存推广任务 → 导入一至两期固定格式证据 → 规则核查 → 查看排查提醒或补证事项 → 人工处理 → 核对结果与版本。

- 导入完成后计算并更新 Web 待处理列表，不要求用户先向模型提问。
- 本增量不实现定时汇总、自动观察、实时采集或基于时钟的重复推送。
- 飞书 #12 为独立联调，不阻塞上述 Web 验收；没有真机证据不得标记飞书可用。
- 不新增模型接入、广告执行、自由编辑预算/出价、创意生成、CSV/Excel 导入、多租户或通用流程引擎。
- 本期人工处理可以保持 changes=[]；完成核查不等于策略改变，更不等于外部投放已经执行。

## 2. 领域对象与边界

以下字段与状态是拟定的逻辑契约，不是已发布接口。实现 PR 必须同时提供类型、运行时校验、版本化迁移、OpenAPI/SDK 和相应测试。
新接口不得只写进对外 OpenAPI 而没有可用处理逻辑。

| 对象 | 拟定信息与不变量 |
| --- | --- |
| 推广任务 Task | id、ownerId、taskVersion、产品/目标/受众、Strategy、观察范围与期限、待确认字段、规则配置；与多次 Session 分开 |
| 证据 Evidence | 稳定 id/revision、taskId、原始固定 JSON、来源引用、导入时间、完整业务口径与内容摘要哈希；版本不可覆盖 |
| 比较 Assessment | 引用确切证据版本和规则版本，status、reasons[]、canComparePeriods、canEvaluateCurrentThreshold、计算结果与缺口 |
| 补证事项 EvidenceRequest | taskId、缺口指纹、所缺信息、原因、核查步骤、完成标准、状态；提交可核验材料后再评估 |
| 提醒 Alert | taskId、指标与当期窗口构成的逻辑事件键，规则版本归属assessment、assessment 引用、事实/局限/处理期限、Session 绑定进度 |
| 决策上下文 | 冻结 taskVersion、Evidence/Assessment 版本、规则版本与原建议；不能通过改摘要偷偷替换依据 |

负责人和渠道操作者分开：ownerId 取自服务端身份；外部 actor 按账户命名空间验证。
所有新增对象的读写、修订、比较和会话关联均检查 owner，不仅列表过滤。

未知预算、出价和启停状态保留为未提供，不补成 0、false 或演示值；现有 Strategy 的可选字段继续可选。
金额语义不完整时禁止金额变更候选，不影响保存任务和非金额核查。
本期不扩展预算/出价操作；将来启用需明确币种、金额单位、预算周期、累计调整上限及旧数据兼容性。

taskVersion 表示任务基线修订；Session.version 继续表示每次成功选择的决策版本。
即使 changes=[]，决策版本也可增加，界面必须显示“已记录决定，草案未变更”。

## 3. 固定证据格式与修订

首版只接收一份固定 JSON，包含 taskId 和一至两期 periods；不做任意字段映射。
一批数据原子保存，失败不遗留半批；一份原始输入最多包含两期。
来源引用用于回溯，不自动抓取或将模型推断写成来源数据。

每期必需表达以下字段；业务信息未知时使用明确的 unknown/待补齐状态，不使用缺字段默认推断：

| 类别 | 内容 |
| --- | --- |
| 来源与统计对象 | 来源/报表名、账户及计划范围、指标 id、咨询按人数还是次数统计、去重与过滤规则 |
| 原始数值 | spendMinor 为非负安全整数，consultations 为非负整数；null 与 0 区分，负数/非有限值拒绝 |
| 金额与公式 | 币种、最小货币单位及比例、公式定义；本期示例咨询成本=消耗÷咨询次数 |
| 时间 | 报表时区、起止边界、统计粒度、数据截至时间、回传是否完整、归因窗口与归因规则 |
| 修订 | 原证据 id/revision、修订原因、来源引用与导入时间 |

统计区间统一为起点包含、终点不包含，保留报表时区；等长按报表日历与粒度核对，不能仅比较日期字符串。
跨期比较要求不重叠；首版自动配对仅使用相邻、等长且已完整回传的期间，其他选期给出原因，不自动拼接。
显示金额可四舍五入，阈值判断用未舍入的原始比例；不先舍入再判断越线。

创建/修订请求采用 owner+操作类型+Idempotency-Key，并保存规范化请求摘要。
同键同内容返回原结果；同键异内容返回 409。
不同键重复导入同一业务内容不生成新证据修订或提醒；内容哈希不能仅依赖文件名、导入时间或随机 id。
修订必须指定预期旧版本；基线已变化返回 409。旧证据、旧判断及已产生的会话均保留。

## 4. 比较资格与当期判断分别计算

采用五种用户可读状态：comparable（可比）、incomparable（不可比）、awaiting_data（待补齐）、missing_baseline（缺少基线）、not_calculable（暂无法计算）。
状态用于说明两期关系；同时返回全部 reasons[]、canComparePeriods 和 canEvaluateCurrentThreshold。
缺少基线不等于当期数据无效，某个历史期不可比也不必然使完整当期失效。

| 情况 | 跨期变化 | 当期越线 |
| --- | --- | --- |
| 两期口径一致、相邻、等长且完整，分母有效 | 可计算 | 配置匹配且满足数据量条件时可判断 |
| 只有完整当期，或历史期与当期口径不同 | 不计算，说明缺基线或差异 | 当期定义与确认的警戒线一致时，可单独判断 |
| 当期回传未完成、关键规则未知、配置未确认 | 不生成相应结论 | 不判断，产生或更新补证事项 |
| 当期咨询为 0、空值或数据量不足 | 不给出有效成本涨跌 | 不输出 Infinity、虚构成本或成本越线结论，展示原值并安排核查 |
| 两期重叠、窗口长度/粒度/时区规则不一致 | 不计算 | 仅在当期自身有效且配置匹配时单独判断 |

机器原因至少区分 missing_baseline、definition_mismatch、scope_mismatch、unit_mismatch、
attribution_mismatch、window_mismatch、incomplete_data、unknown_rule、zero_denominator、insufficient_support。
多项问题一并保留，不靠某个状态吞掉其他原因。
展示优先级为：当期关键数据待补齐 → 明确口径不一致 → 零分母导致无法计算 → 缺少合格历史期 → 可比。零分母保留真实 0，不伪装成缺失。
任一比较被阻断都应给出“缺什么、为什么、如何补齐”。

零咨询不等于没有问题：允许展示“该期记录零咨询，请核查回传与业务记录”，但不伪造可计算的咨询成本。
阈值必须绑定指标定义、币种/单位、统计窗口和归因规则；未知规则不能沿用旧警戒线。

## 5. 补证、提醒与会话

### 5.1 证据不足

未满足判断条件时，先生成或更新 EvidenceRequest：例如补齐归因规则、等待回传、核对报表咨询次数。
本期由确定性模板形成核查清单，用户可以补交来源材料或确认字段；不承诺自动获得平台数据。
后续模型可帮助拟定核查计划，但模型生成的文字不能冒充实测数据、原始报表或新增证据。
同一缺口指纹只保留一项活动事项，重复导入或评估不重复通知；完成需关联新增的可核验证据。

### 5.2 咨询成本越线

规则由用户明确确认：指标定义、成本警戒线、最小消耗、最少咨询次数及统计窗口。
未确认配置产生待补齐事项，不以演示值填入；样例的 70 元仅供合成验收。
当期完整、定义与配置匹配、consultations>0、达到确认的数据量门槛且成本严格大于警戒线时生成排查提醒。
没有合格历史期仍可表达“当期成本超过确认警戒线”，不能写“成本上涨”“恶化”或推断原因。
有合格历史期时才附加前后变化。提醒只支持核查，不据此推荐扩大预算。

本期提醒落入 Web 待处理列表。处理期限来自任务的确认设置；没有期限时显示“未设置”，不包装成限时或紧急事项。
定时汇总与自动 IM 信号推送不在本增量验收中；未来新增调度另写增量设计。

### 5.3 去重、证据修订与推送上限

逻辑事件键为 owner/task、指标身份与当期统计窗口（含时区）；规则版本保存在 assessment，不单独生成新事件。证据 id/revision 不直接充当新事件键。
同内容重新导入、重试、改文案或只切换规则版本，不自动成为可再次推送的新证据。
证据修订追加 assessment，旧判断仍可查；若旧会话仍有可点击候选，必须使其失效，不能原地替换冻结上下文。
只有新增或修正的证据实质改变判断/可处理事项，才允许再次提醒，并记录前次提醒及本次变化原因。

任务配置 maxPushRounds，建议默认 1，必须为正整数；计数对象为同一逻辑事件中的候选卡轮次，首次计入。跨 Session 重建或只切换规则版本不重置计数；新的真实观测期间可形成新事件。
无新证据先停止，不因尚未达到上限而继续推送；上限在生成 Round/投递前由服务端原子校验。
任务/worker 重试不重置计数、不额外创建逻辑轮次；平台重复送达风险仍按 delivery 去重边界说明。
终态结果确认不计入候选卡轮数，但同一操作只创建一条逻辑结果通知，不能借此反复提醒。

“继续观察”改为“待补证后再评估”：结束当前交互、记录补证事项，不立即创建 prepare_round。
新证据经核查与去重后才能启动后续交互。补证任务状态和比较状态不塞入既有 Round 状态机。

### 5.4 Web 会话与一致性

新增显式 web-only 创建方式：不要求真实 IM 账户/操作者，不创建外部发送任务；后端控制台认证和 owner 校验不降低。
旧 IM 创建请求保持兼容；不得以 DEMO_MODE 或伪造收件人冒充此能力。

创建提醒时在同一事务写入逻辑事件、稳定 sessionId 与创建会话任务；worker 以该 id 幂等建立会话，再写回关联。
会话创建成功但关联回写前崩溃时，重跑补齐原关联，不新建第二个会话。准备中/失败在 Web 中可见。
冻结输入的摘要冲突返回 409；旧 taskVersion 或证据版本已失效时不创建/应用旧候选。
新建实体/任务与唯一约束一起迁移，不能把 CREATE IF NOT EXISTS 当成结构升级机制。

## 6. 人工处理和恢复

| 状态 | 用户看到的结果 |
| --- | --- |
| inbox pending | 已收到，处理中；保留同次请求的幂等键，不将 202 当成功 |
| processed 且 changes=[] | 决定已记录，草案未变更 |
| processed 且 changes 非空 | 显示草案 from/to、操作者、决策版本及引用证据；未执行广告 |
| rejected | 操作未生效，展示可读原因，旧轮次/越权/过期不反复重试 |
| failed | 系统处理失败；可查询或按已有授权恢复，不自动换键重复提交 |
| processed 且 delivery failed/cancelled | 业务成功保留，另示通知失败/失效，不把它显示为草案失败 |

客户端跟踪返回的 inboxId，终态停止轮询；建议每 2 秒查询，60 秒后提示“仍在处理中，可稍后查询”，不能把客户端等待超时写成业务失败。
页面离开时取消轮询；刷新后可从会话恢复未终态操作。网络结果未知先查询原操作，再按原幂等键重试。
手动恢复 process_inbox 任务时，必须在同一事务重置可恢复的 failed inbox 与对应 job，保留审计记录；不能仅重试 job 而让业务直接跳过。
恢复前检查 owner、期限、轮次与冻结版本；永久业务拒绝不开放无条件重试。

策略差异先展示现有 budget/bidCpc/enabled，未知值不显示为 0。
默认 reviewPolicy 不产生变更；受控策略变更用例用于验证差异展示，不宣称已接入模型或自动产出营销建议。
