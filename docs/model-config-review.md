## 3. 已复现并修复的问题

| 级别 | 问题与影响 | 修复与证据 |
| --- | --- | --- |
| P1 | 旧临时/部署模型路由默认用全局 fetch，绕过 DNS 绑定与内网拦截 | 改走受控出网；回归测试用回环目标验证拒绝且不触碰全局 fetch |
| P1 | 持久连接探针把 `{}` 当成功，证明不了供应商真的返回可用摘录 | 保存前要求至少一个有效摘录字段；空 JSON → false，创建 503 且不落库 |
| P2 | 覆盖清单把“可调用子集”长度当完整目录数，未接通项显示 0 | 记录 `catalogModelCount` 与 SDK 认证名称，文档显示原始计数 |
| P2 | 供应商带可选 OAuth 就被整家排除，个人 API Key 路径也不可用 | 按已适配协议 + HTTPS + API Key 路径判定；可适配项 20 → 23 → 后续 29 |
| P2 | 模型发现晚到结果覆盖新表单，切换时自定义密钥残留 | 请求序号失效机制；编辑/切换/关闭后丢弃旧结果并清密钥 |
| P2 | `github-copilot` 在三个适配器里走专用认证/动态头分支，却被列为可直连 | 生成器按 SDK 同名分支排除并给出原因，不再假装可用 |
| P2 | 撤销后重设密钥会被自己的墓碑判为已撤销 | 新凭据版本取 `max(凭据版本, 墓碑版本) + 1` |
